# Open Rig roadmap

Updated 2026-09-19. This is the agent-facing ledger; the detailed Explorer
acceptance plan is [`docs/plans/explorer-ide.md`](docs/plans/explorer-ide.md).

## Current baseline

- **Harness:** OpenCode v2 on Ubuntu GNOME/Wayland.
- **Active:** eleven v2 plugin packages, bounded MCP launchers, 19 skills
  (including `development-conventions`, `agent-orchestration`, and
  `session-context`), and the v2
  setup/deployment/health checks.
- **Explorer:** active Phase 1 editor core with explicit saves and safety guards.
- **Fallback:** provider-wide quota routing recognizes Codex, DeepSeek balance,
  and OpenCode Zen free/Go exhaustion; configured tiers form a bounded cyclic
  path, while runtime behavior still depends on provider availability.
- **Provider usage:** the panel tracks verified Codex quota and DeepSeek balance
  plus truthful OpenCode Zen availability/cooldown state; its live details
  dialog is accepted at 120, 80, and 60 columns.
- **Ponytail:** official `4.10.0` content runs through the local v2 adapter;
  bounded daily updates and six commands/skills are active.
- **Agent orchestration:** source/package hooks enforce background-only child
  launches, a three-child hard cap, agent/model allowlists, memory checks,
  nested-agent denial, and policy injection from `opencode.json` plugin
  options. Omitted models resolve through the configured agent after a clean
  shared-service restart.
- **Not claimed:** LSP, formatter integration, full IDE parity, or native
  in-TUI browser embedding.

## Evidence boundary (current)

- `opencode.json` configures `explore` and `general` to
  `openai/gpt-5.6-luna#max`. Orchestration permits background children only and
  enforces a hard maximum of three after host/cgroup memory approval.
- Repeated memory-approved background launches omitted an explicit model and
  resolved the configured `openai/gpt-5.6-luna#max` after clean shared-service
  restarts. Terminal-child capacity was released after parent follow-up.
- The native Subagents panel currently omits model and variant. Plugin/source
  output remains a separate surface and is not native-panel acceptance.
- `/session-context`, `/tools`, and `/learn` render nonblank bounded CLI dialogs
  after the shared-service restart. They do not generate a model turn, resume a
  session, or write synthetic inbox messages. Direct backend behavior remains
  separately verified.
- `/subagents` is a separate, plugin-owned fullscreen session panel. It shows a
  bounded set of same-project/directory child sessions with resolved
  `provider/model#variant` values; it does not modify or equal the native bottom
  Subagents panel because v2.0.7 exposes no supported row-renderer or data hook.
- The portable acceptance-evidence gate passes with nine claims and three
  independently reviewed background records. Pinned headed Chromium launch,
  rendering, interaction, controller, and cleanup are accepted. Installed
  OpenCode binaries remain unmodified and out of scope.

Automated evidence and repository-local, context-bound gate evidence do not equal
deployment or live UI acceptance. Every future item must record automated evidence, live rendered evidence,
interaction evidence, documentation updates, and the exact next action. Do not
start parser or editor-power work merely because the baseline passes.

For an item to leave this boundary, run the portable evidence gate with relative
paths, attach fresh rendered and interaction evidence for each visible claim,
verify direct backends separately from their commands, and record the exact
post-shared-service-restart result. Source or package tests alone are not
sufficient.
